# Interaction lessons

Version: 2.1.0

Last updated: 2026-10-25

This ledger stores generalized methods only. It must not contain raw conversations, customer names, internal numbers, confidential strategy, or unlicensed source material.

## Narrative and content

- Understand the project, audience, and decision goal before designing the page sequence.
- Improve the argument instead of transferring a source deck page by page.
- Supplement thin content with logic, governance boundaries, evidence definitions, ownership, and actions; never fabricate business facts.

## Input handling

- Accept and inventory PDFs, PPTX files, images, logos, VI guides, screenshots, research, and structured data.
- When reusing a reference deck, create a brand replacement map and scan every output for old brand names, logos, filenames, and copied footer text.
- Preserve sources and usage rights for every externally sourced visual or factual claim.

## Visual hierarchy

- Prefer transparent-background logos.
- Place VI, products, scenarios, stores, packaging, screenshots, and evidence images in layouts that match their role.
- Use `contain` for screenshots, VI sheets, full products, packaging, and other assets whose complete silhouette matters.
- Use controlled `cover` only for documentary photography; record the subject focal point.
- Never enlarge weak imagery until it looks soft. Replace, reduce, or frame it.

## Typography and spacing

- Eliminate orphan characters, single-character lines, accidental title wrapping, meaningless crops, and overfilled pages.
- Solve fit by editing copy or changing layout before shrinking type.
- Use hierarchy, grid, whitespace, and a single accent color to create a premium impression.
- Reduce radius, shadows, gradients, and component stacks. Slides should read as compositions, not dashboards.

## Delivery

- Validate page-level visuals, file completeness, and sensitive information separately.
- The web deck, PPTX, and PDF must share content, order, theme, image treatment, and source labels.
- New feedback in the continuing Skill-development thread enters this ledger. Only explicit, reusable improvements become global rules; one-off project preferences stay local.

## Adopted in 2.1.0

- Honor the requested format. PDF-only work stays PDF-first; localized edits preserve the existing deck. Do not rebuild all formats just because the Skill can.
- Preserve the approved visual direction. A request for consistency is not permission to rebrand or restart style selection.
- Separate title, body, number and annotation roles; normalize Chinese spacing and actual available fonts. Do not copy UI pixel sizes into PPT points.
- Encode figures as native tables/charts where editability matters. Keep unknown values distinct from zero, and include units, periods, sources and assumptions.
- Retain real screenshot and product context. Full-image contain is the default for evidence; only intentional crops use a documented focal point.
- Show one main visual or argument per page. Simplify repeated headers, card shells and slogans before removing evidence.
- Distinguish a design rule, renderer implementation, generated file, host import and published version. Verify the exact boundary being claimed.
- Package host-independent instructions and public dependencies. Detect capabilities and report missing support; never silently substitute screenshots for an editable PPTX.

## Adopted in 2.2.0

- Diagnose capabilities before extending the catalog. Many layout names can still map to one composition; count rendered behaviors separately.
- Choose by scenario, page purpose, evidence shape, content capacity and brand constraints. Explain why a layout fits and when it must be rejected.
- Separate popularity from design quality. Preserve original provenance, unknown metrics and reuse rights in reference research.
- Test old and new decisions with the same content before promoting aesthetic lessons; never convert test pass counts into visual scores.
- Distribute only reviewed public rules on the next permitted use; keep runtime upgrades explicit, offline fallback available and current work pinned.
