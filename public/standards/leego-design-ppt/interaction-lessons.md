# Interaction lessons

Version: 2.0.0  
Last updated: 2026-09-01

This ledger stores generalized methods only. It must not contain raw conversations, customer names, internal numbers, confidential strategy, or unlicensed source material.

## Narrative and content

- Understand the project, audience, and decision goal before designing the page sequence.
- Improve the argument instead of transferring a source deck page by page.
- Supplement thin content with logic, governance boundaries, evidence definitions, ownership, and actions; never fabricate business facts.

## Input handling

- Accept and inventory PDFs, PPTX files, images, logos, VI guides, screenshots, research, and structured data.
- When reusing a reference deck, create a brand replacement map and scan every output for old brand names, logos, filenames, and copied footer text.
- Preserve sources and usage rights for every externally sourced visual or factual claim.

## Visual hierarchy

- Prefer transparent-background logos.
- Place VI, products, scenarios, stores, packaging, screenshots, and evidence images in layouts that match their role.
- Use `contain` for screenshots, VI sheets, full products, packaging, and other assets whose complete silhouette matters.
- Use controlled `cover` only for documentary photography; record the subject focal point.
- Never enlarge weak imagery until it looks soft. Replace, reduce, or frame it.

## Typography and spacing

- Eliminate orphan characters, single-character lines, accidental title wrapping, meaningless crops, and overfilled pages.
- Solve fit by editing copy or changing layout before shrinking type.
- Use hierarchy, grid, whitespace, and a single accent color to create a premium impression.
- Reduce radius, shadows, gradients, and component stacks. Slides should read as compositions, not dashboards.

## Delivery

- Validate page-level visuals, file completeness, and sensitive information separately.
- The web deck, PPTX, and PDF must share content, order, theme, image treatment, and source labels.
- New feedback in the continuing Skill-development thread enters this ledger. Only explicit, reusable improvements become global rules; one-off project preferences stay local.
